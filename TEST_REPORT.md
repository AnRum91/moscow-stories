## Что исправлено (причины)

| Проблема | Причина | Исправление |
|---|---|---|
| Тест длительности был `it.fails` | Тест требовал целей ТЗ (30–45 и 90–180 мин), которым текущие данные не соответствуют; он «проходил» только за счёт ожидаемого падения и ничего не защищал. Первопричина — в каталоге слишком мало остановок | `it.fails` удалён. Добавлен контракт `variantInfo` (`src/data/routeInfo.ts`): каждый вариант либо в целевом диапазоне, либо получает явную пометку «Предварительный вариант…», которая показывается в карточке. Тест проверяет это для всех вариантов. **Сами маршруты по-прежнему слишком короткие** (см. ниже) |
| Предупреждение об офлайн-карте зависело от любой сохранённой экскурсии (`saved.some(s => s.withMap)`) | Ошибка логики в `App.tsx` | `mapState(online, tour)` в `offlineState.ts`: состояние считается по выбранному маршруту и варианту. Тест: короткий вариант с картой — `ready`, полный без неё — `no-map`, нескачанный — `not-downloaded` |
| Офлайн показывались остановки нескачанного маршрута | Остановки брались из встроенного каталога независимо от загрузок; список маршрутов и линии на карте тоже | Офлайн остановки берутся только из скачанного пакета; нескачанные варианты в списке отключены («не скачан»), на карте остаются линии только скачанных туров, при открытии из сохранённого состояния показывается карточка «не скачана» без остановок |
| Скачивание оставляло мусор при сбое | Файлы, загруженные до ошибки/отмены, не удалялись | `downloadTour` удаляет временные файлы при любой ошибке и отмене, кроме нужных другим турам; запись о туре создаётся только после загрузки всех файлов и проверки целостности (раньше проверка шла после записи) |
| Удаление при сбое могло оставить «скачано» без файлов | Файлы удалялись раньше записи | Сначала удаляется запись, затем файлы |
| Нехватка места | Не было проверки | `freeBytes/enoughSpace` до скачивания; ошибка `QuotaExceededError` даёт понятное сообщение (протестировано на подставной ошибке) |
| Service Worker | Абсолютные пути (`/sw.js`, `/`) ломались при размещении не в корне (GitHub Pages); `put` падал на частичных ответах (206) | Относительные пути, `base: './'`, регистрация через `BASE_URL`, кэшируются только ответы 200, ошибки `put` не ломают ответ |
| Типы | Не было `esModuleInterop/allowSyntheticDefaultImports` для `import L from 'leaflet'` | Добавлено в `tsconfig.json`; не проверено компиляцией (нет `@types/leaflet`) |
| Сообщения интерфейса | «Доступно офлайн» не различало «с картой / без карты»; скачивание было доступно офлайн | Указано «скачано, с картой / без карты»; кнопки скачивания и обновления отключены без сети |

## Оставшиеся проблемы

1. **Сборка и настоящие тесты не подтверждены** — нужна сеть (см. `BROWSER_SETUP.md`).
2. **Маршруты короче целевого формата.** Оценка по данным: короткие 5–21 мин (цель 30–45), полные 11–37 мин (цель 90–180). Теперь это явно показывается в интерфейсе, но не исправлено: нужны дополнительные проверенные остановки и пешеходная геометрия.
3. Контент демонстрационный: нет источников, фото, аудио; координаты приблизительные; категория «Усадьбы и дворцы» пуста (в фильтре отключена).
4. Тексты по-прежнему входят в JS-бандл, поэтому «недоступно офлайн» для нескачанных объектов — ограничение интерфейса, а не хранилища.
5. Офлайн-карта отключена, пока не выбран поставщик тайлов с разрешением на скачивание (`.env`, см. README). Скачивание и показ тайлов из кэша не проверялись.
6. Не проверены: Service Worker в браузере, IndexedDB/Cache API реально, геолокация, озвучка, внешние ссылки, адаптивность, доступность, работа на телефоне.
7. Версии зависимостей подобраны по памяти и не проверены установкой.
8. Манифест без иконок: установка на экран может быть недоступна.
9. Рабочий процесс GitHub Actions (`.github/workflows/ci.yml`) написан, но ни разу не запускался; версии действий указаны по памяти.
