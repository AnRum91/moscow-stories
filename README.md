# Москва. Истории вокруг (MVP)
React + TypeScript + Vite + Leaflet (+ markercluster). Без серверов и платных ключей.
```
npm install
npm run dev      # разработка
npm test         # vitest
npm run build    # tsc + vite build
```
## Структура
`src/data` — места и маршруты (типы в `src/types.ts`) · `src/services/mapLinks.ts` — адаптеры внешних карт · `geo.ts` — геолокация и расчёты · `offline.ts` — IndexedDB · `components` — UI · `public/sw.js` — Service Worker (кэш оболочки).
## Ограничения
- Весь контент помечен «Демонстрационный материал — требуется проверка»; источников (`Source`) в данных пока нет — их нужно добавить после проверки.
- Координаты приблизительные. Линия маршрута — прямые между точками, не пешеходная геометрия.
- Офлайн: сохраняются тексты и данные маршрута; тайлы карты офлайн не сохраняются.
- Работа deep link-ов во внешних приложениях не проверена; вне приложений открывается веб-версия.
- Нет иконок PWA, фото и аудио, ИИ-помощника, ВДНХ/Коломенского и др.

## Офлайн-карта (важно)
По умолчанию используется публичный сервер OSM **только для онлайн-просмотра**; скачивание тайлов отключено. Чтобы включить офлайн-карту, задайте в `.env` поставщика, чьи условия это разрешают:
```
VITE_TILE_URL=https://<ваш-поставщик>/{z}/{x}/{y}.png
VITE_TILE_OFFLINE_OK=true
VITE_TILE_ATTR=© поставщик, © OpenStreetMap
```
Тайлы вокруг маршрута (зумы 13–16, лимит 800) кладутся в Cache API (`tour-tiles`) и отдаются Service Worker-ом. Поставщик должен отдавать CORS-заголовки.
## Фото и аудио
Поля `image`, `gallery`, `audio` в `Place` готовы, но в данных их пока нет: нужны реальные фото с лицензиями и записанные аудио. Всё, что указано, кладётся в пакет при скачивании.
## Если приложение не открывается
1. Запускать только через `npm install && npm run dev` и открывать адрес из консоли (обычно http://localhost:5173). Двойной клик по `index.html` не работает: это модульное приложение.
2. Нужен Node.js 18+. Геолокация и Service Worker работают на `localhost` или HTTPS.
3. Белый экран: откройте консоль браузера (F12) и пришлите первую красную ошибку.
## Изменения после аудита (фаза A)
- Отметка пройденной остановки: точность GPS должна быть ≤ 50 м, радиус = 25 м + точность; повторно не срабатывает (`services/progress.ts`). Точность GPS показывается в боковой панели.
- Геометрия маршрута хранится отдельно (`Route.geometry`, `geometryStatus`). Пока её нет, линия — прямые между остановками, а карточка показывает «Предварительный маршрут» (`services/routeGeometry.ts`).
- Перед скачиванием проверяется свободное место (`services/storage.ts`); ошибка квоты даёт понятное сообщение.
- Фильтр категорий показывает число объектов; пустые категории отключены.
- `data/validate.ts` проверяет данные (id, координаты в границах Москвы, остановки, статус «проверено» только с источниками). Тест на длительности маршрутов помечен `it.fails`: он проходит, пока маршруты короче целей ТЗ (30–45 и 90–180 мин), и начнёт падать, когда данные исправят.
